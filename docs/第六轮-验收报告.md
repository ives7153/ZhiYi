# 知衣 App 第六轮 — 正式账号系统与用户数据隔离 验收报告

> 本轮范围：复用现有 `User` 主键、资源归属与认证基础，补齐邮箱 + 密码（Argon2id）注册、邮箱验证码核验、登录、忘记/重置密码、修改密码、服务端会话撤销（`token_version`）与个人中心；贯穿后端、签名图片、异步 AI 队列和客户端会话代次（Session Epoch）实现多用户严格隔离；提供受控的旧账号凭据绑定工具；保留前五轮全部功能与历史数据；交付签名 Release APK `v1.0.6` (`versionCode 7`)。

## 2. 关键安全与隔离机制说明

### 2.1 密码存储、验证码约束与防枚举
- **Argon2id 慢哈希**：使用 16 字节随机盐（`os.urandom(16)`），参数 `m=65536` (64 MiB)、`t=2`、`p=4`，输出标准 `$argon2id$v=19$m=65536,t=2,p=4$...` 格式。
- **恒定时间防枚举**：`authenticate_local` 在账号不存在或未设密码时仍执行一次 `verify_password(password, dummy_hash)`，统一返回 `401 邮箱或密码错误`；`/auth/forgot-password` 对未注册邮箱同样返回统一成功文案，不泄露账号存在性。
- **验证码隔离与原子消费**：`auth_verification_codes` 严格绑定 `email` 与 `purpose`（`register` 与 `reset_password` 不可混用），60 秒内重发返回 `429`，有效期 10 分钟，错误尝试达到 `max_attempts=5` 即作废，核验时通过 `SELECT ... FOR UPDATE` 锁定并原子标记 `is_used=True`。

### 2.2 私有图片保护与已签发 URL 有效期边界
- **访问控制**：`GET /api/v1/images/{user_id}/{filename}` 不依赖文件名难猜，必须满足以下任一条件方可读取，否则返回 `401 Access denied`：
  1. 携带有效 Bearer Token，且 `current_user.id == user_id`（或属于同一 `family_id` 授权家庭成员），同时校验 `token_version` 未被撤销；
  2. 携带服务端 `sign_image_url` 签发的有效 `expires` 与 `sig`（HMAC-SHA256 签名，密钥派生自服务端 `SECRET_KEY`）。
- **已签发 URL 的有效期边界说明**：
  - 服务端签发的图片 URL 默认有效期为 `DEFAULT_EXPIRY_SECONDS = 3600` 秒（1 小时），响应头设置 `Cache-Control: private, max-age=3600, must-revalidate`。
  - 过期或篡改 `sig`/`expires` 后，`verify_signature` 立即拒绝并返回 `401`。
  - 客户端 React Query 的 `ITEMS_STALE_TIME_MS = 60_000`（60 秒），远小于 1 小时签名有效期；退出登录时立即清空 Query Cache，且 `<Image key="{userId}:{itemId}:{attempt}">` 绑定当前用户 ID，确保换账号后不会复用上一账号的图片组件实例。

### 2.3 旧账号保留与受控凭据绑定方法
当需要将原有开发模式账号（如 `dev002@example.com`）升级为正式密码账号并保留其名下全部衣物、待购和搭配时，由服务器操作者在后端目录执行：
```bash
cd wardrowbe/backend
.venv/bin/python scripts/bind_credentials.py \
  --user-id 11111111-2222-3333-4444-555555550002 \
  --email dev002@example.com \
  --password 'YourStrongPassword123!'
```
- 脚本会校验 `--user-id` 是否存在且其数据库注册邮箱与 `--email` 完全一致（不一致则拒绝执行，防止误绑或冒领）。
- 绑定后保留原 `User.id` 与 `external_id`，写入 Argon2id 密码哈希、设置 `email_verified=True` 并递增 `token_version`，同时 `/auth/sync` 自动拦截对该账号的任何免密登录请求（返回 `403`）。

## 3. 后端服务启动方式与外部最小配置清单

### 3.1 账号、邮件、AI 和天气所需后端服务启动方式
在本机无 Docker 环境下，一套命令即可启动 PostgreSQL 16.2、Alembic 迁移、Redis 7.2.5、arq 异步任务 Worker 与监听 `0.0.0.0:8000` 的 FastAPI 服务：
```bash
cd wardrowbe
BIND_HOST=0.0.0.0 ./scripts/dev-local.sh start
./scripts/dev-local.sh status
```
- **账号与数据库服务**：由 `dev-local.sh` 自动拉起 PostgreSQL（`127.0.0.1:5432`）并执行 `alembic upgrade head` 至 `6a7b8c9d0e1f`。
- **天气与城市搜索服务**：后端直接调用免密钥的 Open-Meteo API（`https://api.open-meteo.com/v1`），开箱即用。
- **AI 队列服务**：由 `dev-local.sh` 自动启动本地 `redis-server`（`127.0.0.1:6379`）与 `arq app.workers.worker.WorkerSettings`。

### 3.2 外部服务最小待补配置项（配置文件：`wardrowbe/backend/.env`）
