## 3. M2 复核

**校验机制**：`main()` 在进入任何场景之前调用 `ensure_test_account`；它从 `我的` 页读出当前账号邮箱，
与 `$TEST_USER_EMAIL` 比对：一致 → `ACCOUNT_CONFIRMED=1`；不一致 → 用 App 自己的退出登录再登录并复核；
读不到邮箱或切换失败 → `die` 并同时打印双方账号。`login_dev` 也会把读到的邮箱写进日志。

**实测 A（不一致 → 不再拿别人的衣橱判 PASS）**：设备登录 `harness@zhiyi-harness.com`，以
`TEST_USER_EMAIL=review-124937@zhiyi-review.com` 跑 s5（正是独立审查证据 B 的布置，两账号各 1 件）：

```
==> device session email: harness@zhiyi-harness.com (harness expects review-124937@zhiyi-review.com)
[warn] device is signed in as 'harness@zhiyi-harness.com', not 'review-124937@…'; signing out in the app and logging in …
  ok device session switched to review-124937@zhiyi-review.com
  ok cold start 1/2/3: wardrobe rendered and 'review-isolation-132238' is readable
```

三次冷启动断言的**是目标账号自己的物品名**（走的名字分支，不再是计数分支）。

**实测 B（反向）**：设备登录 review 账号、期望 harness 账号时，脚本同样先切换再复核，最终
`ok device session matches the harness account`。

**实测 C（s5 判据收紧的 A/B）**：把 harness 账号造成 1 件、名字含 XML 转义字符
（`harness-amp-&test`；屏上确实显示 `衣柜中有 1 件单品`，计数相符）：

* HEAD 版本的脚本（临时副本，跑完已删除）：`PASS s5-cold-start` — `ok cold start 1/2/3: wardrobe rendered with the server's count (1)`，即**只看计数**。
* 当前工作区脚本：`FAIL s5-cold-start`，三次都打印
  `'harness-amp-&test' (owned by harness@zhiyi-harness.com) is not on screen; a matching count is not accepted`。

→ “名字已知却看不到”再也不能被计数兜底救回来，M2 的核心漏洞已封。

**正常路径无回退**：恢复常规物品名后 `s2 s5` 全绿（s2 三条：改名不伪造人工分类、编辑一致、筛选中文化；s5 名字分支 3/3），
修复后 `s1` 2/2 全绿。`leaked_backend_enums` 抽取为共享扫描器后 s2 行为不变。

## 5. 非阻塞 nit

1. **枚举扫描的 token 表仍是手写的 12 项，且只是 `CLOTHING_TYPES`（31 项）的子集**：`jeans / shoes / suit / hat / scarf / belt / tie / boots / shorts / socks / accessories / polo / tank-top / sweater / cardigan / hoodie / vest / blazer / jumpsuit / sandals` 一旦漏到界面上，扫描不会报错。建议直接从 `src/api/itemVocab.ts` 的 `CLOTHING_TYPES` 派生出 token 表（外加服务端自造的 `unknown`），让扫描与词表不再各写一份。
2. **名字分支用 `grep -F` 直接匹配 XML dump，转义字符必然匹配失败**：`wait_for_text` 读的是原始 `uiautomator` XML，名字里的 `&` 变成 `&amp;`（`<`/`>` 同理），于是“物品就在屏幕上”也会判 FAIL —— 上面 C 组实测就是这条路。测试账号名是 ASCII，影响只在脚手架，但建议改成对 `ui_visible_strings` 的未转义文本匹配（或先把 dump 反转义）。
3. `die` 拒绝路径在打印 TOTAL 汇总之前 `exit 1`，被拒绝的那次运行没有 PASS/FAIL 汇总块（双方账号有打印，符合审查要求）。纯观感。
